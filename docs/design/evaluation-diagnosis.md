# WAM-Mimic 闭环评估问题诊断与根因分析（2026-11-23）

> **本文档定位**：记录对最新纯真实训练版 WAM（`runs/wam-real-5000-b64-dit2-20261122`，5,000 步，解冻 DiT 末 2 Block）在 Genie Sim Q1 / G1 闭环评估中暴露问题的定量诊断、同分布对照实验证据，以及确立 **v2.0 统一标准人体（Canonical Human）五点架构** 的直接依据。

## 1. 观测现象与定量复盘

在 `runs/geniesim-wam-mimic-20261120/replays-real-5000-dit2`（Q1 + WAM 5000 步 + Mimic 12000 步，MuJoCo CPU 闭环）中，6 条评测回合（`press-button` 与 `matching-block-contact` 各 3 个随机种子）呈现出高度一致的失败模式：

| 现象维度 | 实测轨迹数据（`replays-real-5000-dit2/*.jsonl`） | 健康参考基准（`button-retarget-ablation-p0`） |
| :--- | :--- | :--- |
| **终止原因与存活步数** | 全部 **6/6 以 `anchor_ori`（姿态倾斜）提前终止**（89–148 步，1.78–2.96 s） | 107 步成功按下按钮（行程 `3.2–6.6 mm`） |
| **骨盆位移（整机前进）** | 净向后退 **`-22.0 ~ -23.3 cm`**（屁股后撅、上身前倾鞠躬） | 净前进 **`+11.2 cm`**（稳定走向桌前） |
| **双踝运动（迈步能力）** | 几乎原地未迈步，最高抬脚仅 **`5.3–6.4 cm`**；目标踝高反被压到 **`0.9–1.9 cm`**（低于 Q1 站立踝高 `4.1 cm`） | 清晰交替抬脚迈步，最高抬脚 **`10.0–14.1 cm`** |
| **末期目标点异常** | 鞠躬后双踝目标点甩飞至机器人**身后半空**（`x = -0.915 m, z = +0.198 m`），双腕目标被压向地面（`z = +0.208 m`） | 五点目标始终保持在地面上方与可达工作空间内 |
| **第一视角视觉状态** | 躯干下倾后头相机直接朝下拍到 Q1 自身双脚与网格地面，目标物体完全移出视野 | 桌台与目标物持续保持在视野内 |

## 2. 三大核心层面的根因拆解

### 2.1 WAM 与 Mimic 的架构偏离与桥接失配（直接触发“鞠躬正反馈”）

原始核心理念是：**WAM 只在稳定的标准人体（Canonical Human）五点空间规划，Mimic 通过共享编码器将其对齐到 Q1 / Bumi / G1 各机身执行**。但旧实现偏离了该理念，叠加引发 3 处致命失配：

1. **机器人数据未重定向到标准人体五点，导致 G1→Q1 尺度硬碰撞**：
   - `wam-real-5000-b64-dit2` 关闭了 Q1 仿真分支（`sim` 权重为 `0.0`），闭环推理回退至 `embodiment_id = 1`（Unitree G1 分支：`gripper` + `hiw500`）与 G1 统计量。
   - **下肢基准偏差**：G1 站立骨盆到踝高约 `0.745 m`，除以常数 `LEG_LENGTH["g1"] = 0.68 m` 后归一化均值是 **`-1.095`**（OpenHLM）/ **`-0.996`**（HIW-500）；而 Q1 站立为 **`-0.861`**（`0.379 / 0.44`），真人约 **`-0.91`**。
     - **输入侧**：Q1 原始 FK 直接用 G1 统计量做 Z-score，静立状态下脚踝就偏离 **`+7.3σ`（严重 OOD）**。
     - **输出侧**：`q1_direct_targets()` 直接乘 `0.44 m` 还原，将 Q1 脚踝目标压到 `0.420 - 0.44 × 1.09 = -0.06 m`（踩进地里），完全抹杀抬脚迈步信号。
   - **双腕米制未重定向**：旧契约规定双腕保留各构型原始米制。G1 双腕前伸均值 `+21~24 cm`、左右宽 `±20 cm`，而 Q1 臂长仅为 G1 的 `0.647×`。评测未做臂长缩放，直接要求矮小的 Q1 去够 G1 尺度的前伸腕点，Mimic 只能靠弯腰鞠躬+骨盆后撤代偿。
2. **全 3D 骨盆反投影引发“鞠躬失控正反馈”**：
   - `q1_direct_targets()` 用当前带俯仰角的完整 3D 骨盆矩阵 `r0` 反投影局部目标（`goal = pos_local @ r0.T + origin`），同时又把原点 `z` 强行钉在站立高度 `0.420 m`。
   - 一旦 Q1 前倾，局部向下的脚踝向量经 `r0` 旋转会甩到身后半空，双腕目标向下坠向地板，驱动 Mimic 越弯越深，同时头相机（固连于 `torso_link` 且下倾 `27°`）彻底丢失桌面视野，最终触发 `anchor_ori` 熔断。
3. **Mimic 接口误用与旧版检查点短视**：
   - Mimic 的共享 Human Encoder（`goal_kp`）接收标准人体五点，但 Actor Decoder 的必需主路 `ref_feedback`（Global + Ref.）计算的是 **`ref_pos_robot - actual_pos_robot`**，必须输入**已按目标机型精确重定向的机器人尺度五点**。旧 `q1_direct_targets()` 反向把 G1 尺度预测直接塞进 Q1 的 `ref_feedback`，再乘 `1.65` 倒推 `goal_kp`，方向完全颠倒。
   - 同时评测仍沿用旧版 12,000 步 `H=1` 单帧视野权重（`mimic-flip-12000-20261119`），未切换到已训练完毕的 40,000 步 `H=10` 十帧预览权重（`mimic-all-motion-resume12000-40000-20261122`）。

### 2.2 WAM 训练本身的建模与归一化冲突

1. **共享动作空间内的坐标系轴向冲突**：
   - `human-base` / `human-new`（权重 `30%`，`emb_id = 2`）停留在 NOKOV 原始 **Y-up / Z-forward / X-left**（`L_ank mean = [+0.10, -0.91, +0.17]`）。
   - `nymeria` / `nymeria-40`（权重 `25%`，**同样使用 `emb_id = 2`**）、`gripper`（`15%`，`emb_id = 1`）与 `hiw500`（`30%`，`emb_id = 1`）是 **Z-up / X-forward / Y-left**（`L_ank mean = [+0.22, +0.12, -0.86]`）。
   - 四个分支共享同一组 `action_in` / `action_out` / `proprio_enc` 与 `decoder`，导致 Y-up 与 Z-up 在梯度上剧烈对抗。直接证据：`train.log` 中 `nymeria` 5000 步验证损失高达 **`1.807`**，是其余分支（`0.30–0.35`）的 **5–6 倍**。
2. **同一 `embodiment_id` 内的分源独立归一化碰撞**：
   - `train_wam_p1.py` 对每个分支各自用独立 `stats.json` 做 Z-score，但 `gripper`（行走为主，`pelvis mean_x = +0.051, L_ank std_x = 0.177`）与 `hiw500`（原地为主，`pelvis mean_x = +0.003, L_ank std_x = 0.062`）共用 `emb_id = 1`；同一归一化值 `0.0` 对应两种截然不同的物理状态，推理期无法无歧义反归一化。
3. **训练步数严重不足**：
   - 总训练窗口 `1,038,962` 个，5,000 步 × batch 64 仅遍历 **32 万窗口（约 `0.31 epoch`）**，且解冻了 2 层 DiT（`1.49 亿`可训参数），训练结束时损失仍处于明显下降段。

### 2.3 数据质量 Bug 与多样性偏置

1. **严重视频 Bug：`hiw500`（占 30% 训练权重、55.6 万窗口）双目跨缝裁剪**：
   - `BitRobot/HIW-500-LeRobot` 原始 `480×1280` 视频为**左右双目拼接画面（`640×480` 左目 + `640×480` 右目）**。
   - 旧版 `wammimic/data_pipeline/hiw500.py` 使用居中裁剪 `crop=ih:ih:(iw-ih)/2:0`（截取 `x ∈ [400, 880]`），恰好横跨 `x = 640` 双目拼缝，导致全部 `hiw500` 训练帧均为**中缝断裂的左右目拼图**，严重破坏视觉几何学习。
2. **强烈的“定脚原地、只动手臂”数据偏置**：
   - `hiw500`（`30%`）：`pelvis mean_x = +0.003`（约 `2 mm/s`），绝大部分片段为站在原地微调姿态操作。
   - `human-new`（占 `human_protocol` 152/175 回合，分支权重 `30%`）：大量任务指令明确约束 *“Keep both feet on the marked spots for the whole take. Do not step.”*。
   - `nymeria` 旧 3 条：基本为坐姿写白板（`L_ank z = -0.454`）。
   - 真正稳定包含“迈步走近桌台 → 伸手操作”的 Z-up 数据仅 `gripper`（`15%`）与受轴向冲突拖累的 `nymeria-40`。
3. **相机光学畸变与 Sim-to-Real 域差**：
   - OpenHLM 为 **180° 圆形鱼眼镜头**（四周黑边，视野底部含 G1 胸甲与双臂），而 Genie Sim 为无畸变针孔相机 + 纯蓝格子地面，且训练完全未含仿真样本。

## 3. 同分布 Genie Sim 场景对照实验证据（2026-11-23）

为剥离“场景 OOD”、“桥接/Mimic 失配”与“跨构型迁移误差”三个因素，我们在 Genie Sim 中复现了训练集中高频存在的 **OpenHLM `task_0`** 场景（白色 `table_000` + 橙色鼠标垫 + 红色易拉罐，直接使用训练集预编码 `task_0` 文本潜码：*"Walk forward to the table, put the red can on the orange mouse pad with the right hand, turn around and walk back."*），在 MuJoCo CPU（200 步 = 4.0 s，Seed 0/1）上完成 4 组控制变量实验（产物位于 `runs/geniesim-wam-mimic-20261120/replays-indist-20261123`）：

| 对照组（同一 WAM 5000 步权重） | 机身与场景尺度 | 桥接与 Mimic 版本 | 存活步数（/200） | 终止原因 | 骨盆净位移 `dx` | 双踝净位移 `dx` | 核心结论 |
| :--- | :--- | :--- | :---: | :---: | :---: | :---: | :--- |

### 实验确立的纠偏路线

对照实验用硬数据证明了三个结论，直接决定了后续重构方向：
1. **必须回到“统一标准人体（Canonical Human）Z-up 五点空间”**：只要不同数据源（人类光学、人类惯导、G1 实机）各自保留自己的坐标轴、臂长米制与踝高基准，跨构型（如 G1 数据训 WAM → Q1 闭环执行）就必然崩坏；把所有数据源统一重定向到同一个标准人体五点空间后，WAM 才真正构型无关。
2. **必须用 Yaw 航向系 + 双向运动学重定向替代 `q1_direct_targets()`**：输入侧把目标机器人 FK 映射到标准人体五点，输出侧由标准人体五点直通 Mimic `goal_kp`、并经 Yaw 航向系精确重定向到目标机型供给 `ref_feedback`，搭配 Mimic 40k（H=10）即可彻底消除鞠躬正反馈。
3. **必须立即修复 `hiw500` 双目裁剪 Bug 并重平衡“行走+操作”数据分布**：原生 G1 虽然已能前行 ~30 cm，但受 `hiw500` 画面断缝、定脚静止片段占比过高以及鱼眼/针孔视觉域差影响，步速偏慢且近场精细落点尚未收敛。
