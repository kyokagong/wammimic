## 1. 当前存量数据诊断与核心缺口

结合现有 `protocol.json`、离线评估报告及 `source_audit.json` 审计结果，当前 WAM 训练数据存在四大结构性瓶颈：

| 问题维度 | 当前存量现状 | 导致的直接症状 |
| :--- | :--- | :--- |
| **训练会话规模过小** | 仅 **18 个录制会话**（17,868 个步长 1 帧的高重叠窗口；操作补充包仅 **2 个训练会话 / 1,484 窗口**） | 训练 5,000 步（~13 epochs）后严重背诵背景与轨迹，留出测试集 ADE `262~269 mm` 劣于常数均值 `230~235 mm` |
| **任务与视觉域差极大** | 100% 为 ~1.7m 真人实拍（走路、推车、搬箱、开抽屉），**0 条**“按桌面按钮 / 选色触碰积木 / 仿真渲染”样本 | 零样本测在 0.88m Q1 MuJoCo 桌面场景中完全 OOD，无法将视觉和指令映射到伸手按压 |
| **缺失本体状态输入** | 当前 `HumanWAMDataset` 仅提供 2 帧压缩视频潜码 + 文本，无历史五点状态/速度，且头相机看不到垂在身侧的手 | `0.2s` 短时位置误差高达 `165~183 mm`（对比常速参考仅 `38 mm`），无法做闭环视觉-本体伺服 |
| **缺失异构末端监督** | 人体主线 `end_effector_supervision = False`；本地 `OakInk2` 缺图像、`MotionDecode` 缺配对第一视角视频 | 无法训练 `bimanual_parallel_gripper`（47D）与双灵巧手（57D/59D）的 `embodiment_tag` 专属解码头 |

## 2. P1 分优先级数据补全清单（D1 → D4）

建议严格按 **D1 → D2 → D3 → D4** 顺序补齐，每完成一层即可触发一次容器化增量处理与闭环验证。

### 优先级 D1（最高优先级）：仿真闭环“移动—桌面操作”合成数据集（`Sim-LocoTabletop`）

**核心目标**：最快速度打通“Q1/G1 第一视角渲染画风 + 小机身视高 + 手物同框 + 按按钮/触碰/抓取任务”的闭环泛化。

| 配置项 | 规格要求 |
| :--- | :--- |
| **任务覆盖** | 1. **桌面按按钮（`press_button`）**：随机桌子高度、按钮平面位置/颜色、起步距离（$0.20\text{–}1.20\text{ m}$）及可选椅腿绕障<br>2. **选色触碰与推拨（`matching_block_contact`）**：多颜色多物体桌面布局 + 自然语言选物指令<br>3. **移动抓取与交接（`loco_bimanual_grasp`）**：双手夹爪 / 双灵巧手接近、预塑形、抓取提举 |
| **建议数据规模** | **首期闭环验证（MVP）**：`500 ~ 2,000` 条独立成功回合（约 `1.5 万 ~ 8 万` 有效 10Hz 窗口）<br>**正式泛化基线**：`5,000 ~ 20,000` 条多场景随机化回合（按布局/随机种子严格隔离 `train/val/test`） |
| **视觉与域随机化** | `10 Hz`、`224×224` RGB；覆盖 Q1/Bumi/G1 对应相机安装高度与俯角（在标称俯角基础上注入 $\pm 3^\circ$ 随机扰动）；随机化地面纹理、桌面材质、环境光照与背景，避免过拟合单一棋盘格 |
| **轨迹设计硬要求** | 1. 必须包含**“近场抬手同框”**：距目标 $< 0.45\text{ m}$ 时提前抬起工作臂进入头相机视野，建立视觉相对定位先验<br>2. 同时提供多句式指令改写（每类任务 ≥ 15 种自然语言表达） |
| **必须采集的字段** | `observation.images.cam_head`、`observation.state`（过去 4 帧虚拟骨盆系五点位姿/速度 + 末端开度/指节及残差 $\Delta\mathbf{q}_{\text{ee}}$）、`action`（`10 × (45 + D_ee)`，统一锚定在 $t_0$ **水平朝向系**或严格记录锚点 3D 四元数）、同源 `50 Hz` 机器人全身关节轨迹（经 `traj_id` 与 Mimic 库关联） |
| **推荐来源与生成方式** | 直接复用现有 `Genie Sim` 场景资产 + `MuJoCo Warp / Isaac Lab` 4×4090 无头渲染，基于 `button_reference` / 运动规划器 / 专家策略批量 rollout 采集 |

### 优先级 D2：真实人类第一视角光学动捕扩充集（解决 WAM 18 会话过拟合）

**核心目标**：将真实人体五点先验从“18 个会话过拟合”提升至“跨参与者、跨场景稳定优于 `training_mean` 且旋转角误差 $< 20^\circ$”。

| 数据源 | 当前状态 | 需补全内容与目标规模 | 接入与质量硬门槛 |
| :--- | :--- | :--- | :--- |
| **`BitRobot/robomocap` 扩充包** | 仅 18 个训练会话（操作类极度匮乏） | 扩充至 **≥ 100 ~ 300 个独立录制会话**（总有效窗口 $\ge 10\text{ 万}$）。重点补足 `static_manipulation`、`locomanipulation`、`environment_coupled_wholebody`、`long_horizon_composite`，要求**每个操作家族训练集 ≥ 15 个会话、覆盖 ≥ 10 位参与者**，且优先挑选桌面伸手、按压、抓放、转身绕障片段 | 保持 `30 Hz` RGB + `120 Hz` 光学骨架同步；`lag_scatter_ms <= 5 ms`；通过 BVH/NPZ 独立前向复核；同一 `recording_group` 与视频哈希严禁跨 `train/val/test` 泄漏 |
| **`Nymeria` 第一视角全身室内集** | 本地仅元数据，缺录制文件 URL 清单 | 补齐官方录制包（室内多房间行走、绕家具、桌面日常操作，建议 **≥ 50 ~ 100 小时**有效片段） | 需单独标注为 IMU/惯导骨架参考协议（与 NOKOV 光学动捕区分 `label_provenance`），经时间同步与姿态突跳过滤后作为通用室内移动操作预训练扩充 |
| **本体历史状态导出升级** | 现有 `human_ego` 未导出历史姿态 | 在现有及新增人体数据 ETL 中，同步导出**过去 4 帧（`t0-0.3s .. t0`）相对 $t_0$ 的五点位姿与线/角速度**作为 `observation.state`（评测时同样由机器人实测 FK 提供，无特权泄漏） | 严格因果：历史速度仅由 $t \le t_0$ 的实测帧差分计算，严禁混入未来帧滤波斜率 |

### 优先级 D3：机器人全身遥操作与异构末端执行器数据（`embodiment_tag` 路由训练）

**核心目标**：填补 `end_effector_supervision = False` 空白，支撑 GR00T N2 风格“共享动作主干 + `embodiment_tag` 三模块路由”同时适配球头、双手夹爪与双灵巧手。

| `embodiment_tag` | 目标动作维度 | 需补全的数据来源 | 目标规模与关键字段 |
| :--- | :---: | :--- | :--- |
| `bimanual_stub` | `10 × 47` | 由 D1 仿真按按钮/触碰回合 + 人类按压样本提供 | `45D` 五点 + `[l_touch, r_touch]`，需记录物理接触力阈值触发时刻 |
| `bimanual_parallel_gripper` | `10 × 47` | 1. 扩充 `OpenHLM` / G1·Q1 桌面抓放遥操作数据<br>2. D1 仿真夹爪抓放合成数据 | **≥ 300 ~ 1,000 条**完整抓放回合；必须含 `observation.images.cam_head`、实测夹爪开度及跟踪残差 $\Delta q_{\text{ee}}$、URDF 正解（FK）反算的 `45D` 五点 + 连续开度目标 `[0, 1]^2` |
| `bimanual_dex_6dof`（6-DoF 五指手）<br>`bimanual_dex3_7dof`（Dex3-1 三指手） | `10 × 57`<br>`10 × 59` | 1. **补齐带第一视角图像的真实手物集**：补全 `OakInk2` 同步图像流或 `ARCTIC` / `MotionDecode` 带第一视角视频与手部骨骼的完整发布子集，经 DexPilot 重映射派生双灵巧手标签<br>2. **机器人灵巧手遥操 / 仿真数据**：G1+Dex3-1、Q1+6-DoF 灵巧手桌面抓放与交接回合 | 每类灵巧手构型 **≥ 200 ~ 500 条**有效操作回合；记录手指预塑形（Pre-shaping）至包络闭合完整过程、实测关节角与残差 $\Delta\mathbf{q}_{\text{ee}}$，并标明腕部法兰至 TCP 偏置 $\Delta x_{\text{tcp}}$ |

### 优先级 D4（Stage 3 闭环衔接）：WAM 预测 `465D` 回灌配对数据

**触发时机**：当基于 D1–D3 训练的新版 WAM 在留出测试集上**稳定超越 `training_mean` 基线**（建议门禁：离线操作集 `ADE < 120 mm`、旋转角误差 `< 20°`）后执行，无需人工新采原始视频。

* **生成方式**：使用数据管线容器运行 `PIPELINE_STAGE=build_rollout`，对共享轨迹执行 WAM 批量推理，将实际预测出的 `10×45` 五点序列按与评估一致的桥接器组装为 **`465D` 预测窗口**，并与同源真值机器人全身关节轨迹配对存入 `${PROCESSED_DATA_ROOT}/wam_rollout_5pt_store/`。
* **配比与扰动**：在 Mimic Stage 3 续训中与干净 `465D` 数据按 **50:50** 混合，并开启 `kp_jitter = true`、`kp_drift = true` 与随机末尾帧掩码，使 Mimic 原生免疫 WAM 预测噪声与块间跳变。

## 3. 新补数据目录接入与验收门禁（Phase 0 容器规范）

1. **环境变量组织方式**：将新下载或新合成的原始数据放置于 `${RAW_DATA_ROOT}` 下各自独立的子目录，在 `conf/data/pipeline.yaml` 中按相对子路径注册，通过只读挂载 `/mnt/raw_data:ro` 交给 `docker/Dockerfile.data` 容器增量处理（自动基于 `SHA256` 跳过已处理分片）。
2. **统一输出契约**：
   * 面向 WAM 的全部新增数据集统一导出为 `LeRobot v2.1 + GR00T` 格式（`meta/{info.json, modality.json, embodiment.json, stats.json, episodes.jsonl, tasks.jsonl}` + `data/*.parquet` + `latents/*.safetensors` + 全局 `prompt_bank_bf16.safetensors`）；
   * `stats.json` 必须仅在最终 `train` split 上重新拟合；**严禁按帧随机划分**，必须按整段录制会话或独立仿真场景布局划分 `train / val / test`。
3. **开训前必过的数据 QA 门禁（`qa_validator.py`）**：
   * **坐标系与桥接闭环自检**：新增数据集抽样轨迹送入 P0 修复后的 `human_features -> block_targets` 往返校验，位置还原误差须 `< 1 mm`、旋转还原误差 `< 0.1°`；
   * **数值合法性**：零 `NaN/Inf`、`rot6d` 正交残差 $< 10^{-4}$、无追踪突跳漏筛；
   * **Rerun 3D 目视抽检**：每类新增数据源随机导出 20 条 `.rrd`（叠加头相机 RGB、45D 五点坐标轴簇、机器人网格与末端曲线），确认左右手符号、夹爪开合方向（`0=开, 1=闭`）及手物同框比例正确后再启动 Stage 2 训练。
